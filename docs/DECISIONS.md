One line per decision. To change your mind, add a new row that supersedes the old one, and never rewrite history. The GDD is updated to match each decision; this file records *what* was decided, *when* and *why*.

**Two id series (since 2026-10-07).** The original rows use D1-D12 (design), P1-P3 (platform and process), C1-C4 (copy), W1 onward (workflow) and A1 onward (agent defaults). The Run Spec v1 rows, merged on 2026-10-07 (W8), keep the spec's own ids, with a hyphen and two digits: D-01..D-25 (its decisions), P-01..P-08 (its proposals, accepted on 2026-10-07) and Q-01..Q-07 (its open questions, answered or set to the spec's default). They are different rows: D-12 (the Codebase is the core system) is not D12 (the VS intro), and P-01 (floor depth) is not P1 (iPhone first). Design decisions made after the merge continue the hyphenated series (D-26 onward, A60), so a new id never looks like an old one. The spec's assumptions A-01..A-05 are not agent defaults; they live in GDD 13.2. In the Run Spec rows, **Yours** means the developer stated it, and **Unchallenged** means the spec proposed it and the developer didn't object, so it can still be reopened. **MC-nn** points to an open conflict in `docs/merge-report.md`.
